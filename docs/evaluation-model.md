# Evaluation Model

このリポジトリは、エージェントの能力を「構成」「振る舞い」「実運用」の3層で評価する。

## 1. 評価対象の分離

### 静的構成評価

対象:

- `evals/run_evals.py`
- Skill、ツール、設定、評価用ファイルの存在
- ルールや契約の構造健全性

わかること:

- 必要な構成要素が存在するか
- 評価ハーネスやSkill定義が壊れていないか

わからないこと:

- エージェントが実運用でその能力を発揮できるか
- 改善が実際に効果を持ったか
- Level 7以上へ到達したか

静的評価のPASSやスコアは、実運用Levelの直接的な証明として扱わない。

### 振る舞い評価

対象:

- `evals/run_behavior_evals.py`
- 決められたシナリオに対する回答、仮想アクション、tool trace

わかること:

- 固定条件下で期待する振る舞いが再現されるか
- provider、model、prompt、Agent実装、仮想ツールの組み合わせが契約を満たすか

振る舞い評価は実運用に近い証拠だが、固定シナリオの結果だけで総合Levelを確定しない。

### 実運用Level評価

対象:

- 実際の案件・作業での継続的な能力発揮
- 実行結果、改善前後の比較、失敗からの復旧、反復性

実運用Levelは、静的スコアの最大値ではなく、証拠で確認できた最上位能力を保守的に判定する。証拠が不足する場合は、下位の確認済みLevelまたは「判定不能」とする。

## 2. Level 7の判定境界

Level 7「自己進化と環境改善」は、次の一連の流れが実運用で確認できた場合に限り候補とする。

```text
改善余地を自律的に発見
→ 改善案を選択
→ 許可された範囲で改善を実行
→ 改善前後を同じ指標で測定
→ 失敗時に復旧または別案へ切り替え
→ 同じ構造を再現
```

Skillやmemory、評価器、cronが存在するだけでは、Level 7の実運用証拠にならない。

## 3. PhaseとLevelの関係

Phaseは実装・検証工程であり、Agent Levelそのものではない。

特にPhase 2.3「オープンエンドループ」の7日稼働は、継続実行の証拠を追加する工程である。7日間の稼働や新規結果数の達成だけでは、Level 7の自己改善能力やLevel 8への移行を証明しない。

各Phaseの結果は、次の形式でLevel評価へ接続する。

- 今回のPhaseで確認できた能力
- 追加された実運用証拠
- まだ確認できない能力
- 現在Level判定への影響
- 次に必要な検証

対応関係が定義されていない場合は、無理にLevelへ写像しない。

## 4. 報告フォーマット

```text
現在Level（実運用で確認できた最上位能力）:
静的構成インベントリ:
振る舞い評価:
確信度:

今回の目的:
今回追加された証拠:
次Levelに不足する能力:
今回のPhase／実験の意味:
結論: 進む／継続観測／止める／判断不能
次のアクション:
```

評価対象のエージェントごとの現在地や証拠は、評価対象側の環境・成果物に保存する。この汎用リポジトリには、特定エージェントの未確認な現在Levelや運用実績を記録しない。
