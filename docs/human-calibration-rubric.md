# Human Calibration Rubric

更新日: 2026-09-16
状態: 初版（実会話4件で適用）

## 目的

Human Calibrationは、Traceが存在するかではなく、問いの形成・更新・意味づけが妥当だったかを人間が確認するために使う。ユーザーの評価は事業成果の証明ではなく、会話ケースに対するドメイン評価として扱う。

各軸は必ず `pass`、`partial`、`fail`、`not_observable` のいずれか1つを付ける。

- `pass`: 観測可能な範囲で、評価対象の行動・判断は十分に妥当
- `partial`: 方向は妥当だが、ユーザー依存・不足・過剰解釈が残る
- `fail`: 評価対象の行動・判断を明確に取り違えた、または必要な修正を反映しなかった
- `not_observable`: 会話のEvidenceだけでは判定できない

## 評価前の原則

1. 最終回答の出来だけでなく、初期問いから更新までの軌跡を見る。
2. ユーザーが重要な再定義を指示した場合、最終品質が高くても自律的Evidence更新とは評価しない。
3. 顧客購買、予算、採算、事業効果は、会話だけで確認できなければ`not_observable`または`partial`にする。
4. 意図的に次工程へ送った論点を、未達や失敗と混同しない。
5. 外部資料を取得できなかった場合、取得できた前提で評価しない。

## 5軸の判定基準

### 1. `initial_question_capture`

**見るもの**：会話開始時点で、ユーザーが解こうとしていた問い・対象・用途を捉えたか。

- `pass`
  - 問いの対象、判断用途、主要な制約を初期から正しく押さえた
  - 問いが粗くても、粗さを保ったまま適切に扱い、勝手に単純化していない
- `partial`
  - 大枠は合っているが、択一化、対象レイヤーの混同、前提の欠落がある
  - 会話のラリーで修正され、最終的に妥当な問いへ到達した
- `fail`
  - 顧客、用途、対象資料、意思決定者などを取り違えたまま進めた
  - ユーザー訂正後も初期フレームを維持した
- `not_observable`
  - 初期意図を判定できる材料がない

### 2. `evidence_driven_update`

**見るもの**：新しいEvidenceを受けて、問い・仮説・方針を更新したか。

- `pass`
  - 会話または外部Evidenceが、更新前後の差分と明確に結びついている
  - ユーザーの指示だけでなく、確認済みEvidenceの内容も更新理由に含まれる
- `partial`
  - 更新は起きたが、主な駆動要因がユーザーの訂正・指示である
  - Evidenceは参照されるものの、更新への因果関係が弱い
- `fail`
  - 反証・訂正・新情報を受けても問いを更新しない
  - 既存出力を前提にし、Evidenceと矛盾する方針を維持する
- `not_observable`
  - 更新前後またはトリガーEvidenceが記録されていない

### 3. `question_update_rationale`

**見るもの**：なぜ問いを更新したのかという理由が、Evidenceと整合しているか。

- `pass`
  - 更新理由が、観測された制約・反証・役割分界・市場事実などに対応している
  - ユーザー指示に従った場合も、その指示の意味を正確に説明できる
- `partial`
  - 更新方向は妥当だが、理由が「ユーザーが言ったから」に留まる
  - 根拠はあるが、更新とのつながりが説明不足
- `fail`
  - 実際に観測されていない理由を後付けした
  - 更新理由がEvidenceと矛盾する、または単なる印象・流行語である
- `not_observable`
  - 更新理由を確認できるTraceがない

### 4. `decision_proximity`

**見るもの**：更新後の問いが、次の事業判断・検証行動に近づいたか。

- `pass`
  - 誰が、何を、どの条件で判断するかが明確になり、次の検証が実行可能
  - 判断を変えるEvidenceと、判断後の分岐が定義されている
- `partial`
  - 問いは具体化したが、顧客・予算・採算・責任者・実行結果の一部が未確認
  - 次の検証は示されるが、まだ事業判断そのものではない
- `fail`
  - 抽象的なスローガン、資料改善、機能列挙に留まり、判断条件が明確にならない
  - 更新後も元の不確実性を減らせない
- `not_observable`
  - 会話から事業判断への距離を評価できる材料がない

### 5. `feedback_interpretation`

**見るもの**：ユーザーの訂正、拒否、肯定、受入を区別し、方針に反映したか。

- `pass`
  - `correction`、`rejection`、`positive_signal`、`acceptance`を取り違えず、適切に反映した
  - 肯定を事業成果や購買意思へ過剰解釈していない
- `partial`
  - 大筋では反映したが、確信度・シグナルの意味・訂正範囲が曖昧
  - ユーザーの追加指示があって初めて修正できた
- `fail`
  - 拒否を肯定、訂正を追加要望、保留を承認などと誤読した
  - ユーザーの明示的な修正後も同じ誤りを繰り返した
- `not_observable`
  - 明示的なユーザー評価シグナルが記録されていない

## 評価者間比較

同じ匿名化ケースを評価者A・Bが独立に判定する。先にAの判定を見せてBを誘導しない。

軸ごとに次を出す。

- `agreement`: 同じラベル
- `overcall`: AがBより強く評価（例：A=`pass`、B=`partial`）
- `undercall`: AがBより弱く評価
- `unobservable_mismatch`: 一方が`not_observable`、他方がそれ以外

一致率は単純一致件数 ÷ 比較可能な軸数で計算する。ただし、ケース数が少ない間は統計的な信頼性を主張しない。意見が割れた軸は、ラベルを平均化せず、根拠を再レビューして基準を修正する。

## 現在の限界

- 現在の4件は単一ユーザーによる評価で、評価者間一致度は未確認
- 現在の構造Evaluatorは5軸の意味判定をしていないため、自動評価との一致率は未算出
- 実会話のEvidenceは匿名化・構造化されており、元会話全文の再読による再現性は制限される
- Human Calibrationは顧客成果、収益、購買意思の代替ではない
