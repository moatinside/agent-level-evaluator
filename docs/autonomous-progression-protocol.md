# Autonomous Progression Protocol

## Purpose

エージェントレベルを「採点表」で終わらせず、現在地から次のチェックポイントの実行・検証までを起動するための運用規約。

## Non-negotiable rule

> **評価結果に未完了チェックポイントがある場合、報告だけで終了してはならない。**
> 次の実行計画を生成し、実行可能なら着手する。実行できない場合は、阻害要因・必要な判断・再開条件を記録する。

## State model

各チェックポイントは、次の4状態のいずれかで管理する。

| 状態 | 意味 | 次の動作 |
|---|---|---|
| `未着手` | 定義はあるが計画・証拠がない | 実行計画を作成し、着手する |
| `計画済み` | 計画はあるが実行証拠がない | 計画を実行する。設計追加は禁止 |
| `実行中` | 実行を開始し、完了条件が未達 | 次の作業を継続するか、阻害要因を記録する |
| `検証済み` | 完了条件・テスト・証拠が揃った | 次の未完了チェックポイントへ移る |

`CHECKPOINTS.md` の `[ ]` は、`検証済み`の証拠がない限り `[x]` に変更してはならない。

## Required transition

```text
評価
  ↓
最初の未完了チェックポイントを特定
  ↓
実行計画を作成（目的・対象ファイル・コマンド・完了条件・阻害時の扱い）
  ↓
計画を保存
  ↓
実行
  ↓
テスト／実行ログ／生成物を確認
  ↓
完了条件を満たした場合のみ進捗を更新
```

## What the evaluator must output

毎回、次の5項目を必ず出力する。

1. 現在のPhaseと未完了チェックポイント
2. 最初に着手するチェックポイント
3. 今回実行する最小作業
4. 完了を証明する成果物・テスト・ログ
5. 実行できない場合の阻害要因と再開条件

## Stagnation rule

同じチェックポイントが2回連続で未着手の場合、通常の評価レポートを出して終わることを禁止する。

- `status: blocked` として阻害要因を出力する
- 実行計画ファイルを作成する
- 人間の承認が必要な場合だけ、承認事項を1つに絞って提示する
- 承認不要のローカル実装・テストは、その場で実行する

## Evidence rule

Phase移行に使える証拠は、最低限次の3点とする。

- 実行可能な成果物（コード、設定、または再現可能な手順）
- 合格条件を検証するテスト結果
- 入力・実行日時・結果を含む実行ログ

設計書、スキル本文、自己申告スコア、ファイルの存在だけでは、実行証拠とはみなさない。

## Human boundary

エージェントは、次を自律的に実行してよい。

- ローカルの計画作成、コード実装、テスト、ログ保存
- 既存の承認済み環境での評価実行
- 失敗原因の切り分けと再試行

次は、事前に人間の承認を必要とする。

- 外部公開、顧客・第三者への送信
- mainへのpush（このリポジトリでは、ユーザーが明示的に許可した場合を除く）
- 継続的なcron運用の新設・変更
- 有料API、破壊的操作、権限変更

## Definition of done for Phase 2.1

Phase 2.1を完了扱いにできるのは、以下をすべて満たした場合だけとする。

- 評価可能な関数と初期解が定義されている
- 複数世代の候補生成・評価・選抜が実行できる
- 初期解を上回る結果が実測されている
- ランダム探索との比較結果が保存されている
- 再実行コマンドと実行ログが保存されている

## Required guard

```bash
python3 scripts/progression_gate.py
```

このコマンドは、最初の未完了チェックポイントと、実行計画・証拠の不足を表示する。未完了のまま進捗を完了扱いにする処理は実装しない。
